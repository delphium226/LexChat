# AILA (LexChat) — Server API Specification

**Base URL**: `/api`

Interactive docs (generated by FastAPI from the routers; the OpenAPI `version` is the release in `VERSION`):
- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`

General behaviour:
- Every response carries an `X-Request-ID` header. An inbound `X-Request-ID` (from a reverse proxy or a federation caller) is honoured; otherwise one is minted. All log lines for the request share it.
- When the built client (`client/dist`) is present, any path not matched by a route is served the SPA's `index.html`, except paths under `/api/`, which return `404 {"detail": "Not Found"}`.
- Request bodies are validated by pydantic. A missing required field or a wrong type returns `422`. Unknown keys are ignored, not rejected.

## Authentication

JWT-based. The token is delivered in an HTTP-only `token` cookie on login and is also returned in the login response body. The server reads the cookie first, then an `Authorization: Bearer <token>` header (the header is for machine callers; the browser client relies on the cookie).

There is no global auth middleware: each route declares its own dependency. In this document:
- **Public**: no dependency; no token needed.
- **Auth required**: any valid token (`get_current_user`). A few routes also load the user's database row and return `404` if the account no longer exists.
- **Admin only**: token with role `admin` (`get_admin_user`, or an equivalent role check inside the handler).

Unauthenticated requests to a protected route return `401`; an authenticated non-admin calling an admin route gets `403`.

Tokens expire after 7 days, or 30 days with `rememberMe`. Federation tokens (`POST /api/auth/federation-token`) carry no expiry.

## 1. Auth (`/api/auth`)

### POST `/api/auth/login` — Public
```json
// Request
{ "username": "string", "password": "string", "rememberMe": false }

// Response 200
{
  "token": "jwt_string",
  "user": {
    "id": 1, "username": "string", "role": "user|admin",
    "dark_mode": false, "research_mode": "legislation_only", "chat_mode": "research"
  }
}
```
Also sets the HTTP-only `token` cookie (`SameSite=Lax`; `Secure` only when the client connection is HTTPS, read from `X-Forwarded-Proto` behind a proxy). Writes a `LOGIN` row to the activity log. Wrong username or password: `401 Invalid credentials`.

### POST `/api/auth/logout` — Public
Clears the `token` cookie. Returns `{ "message": "Logged out successfully" }`.

### POST `/api/auth/federation-token` — Admin only
Mints a **non-expiring** admin token (`scope: "federation"`) for use as a peer credential: it is the value a sibling bot stores as this bot's `api_key` in its peer registry (§14). Returns `{ "token": "jwt_string" }`.

### GET `/api/auth/me` — Auth required
Returns the current user, wrapped:
```json
{ "user": { "id": 1, "username": "string", "role": "user|admin", "dark_mode": false, "research_mode": "legislation_only", "chat_mode": "research" } }
```
`404` if the account no longer exists.

### POST `/api/auth/reset-password-request` — Public
```json
// Request
{ "username": "string" }
// Response 200 — always 200, whether or not the user exists (prevents enumeration)
{ "message": "If user exists, a password reset email has been sent." }
```
No email is sent in this build; the request is logged (with the address redacted).

### POST `/api/auth/change-password` — Auth required
```json
// Request
{ "currentPassword": "string", "newPassword": "string" }
// Response 200
{ "message": "Password updated successfully" }
```
Wrong current password: `400 Incorrect current password`.

### PUT `/api/auth/preferences` — Auth required
```json
// Request (all fields optional; only those present are changed)
{
  "dark_mode": true,
  "research_mode": "legislation_only|case_law_only|legislation_and_case_law",
  "chat_mode": "conversational|research|deep_research"
}
// Response 200
{ "message": "Preferences updated" }
```
Values are stored as sent; they are not validated against the vocabularies above.

## 2. Chats (`/api/chats`) — Auth required

Every route acts only on the caller's own chats; another user's chat or message returns `404`.

### GET `/api/chats`
Returns the caller's chats ordered by `created_at DESC`.
```json
[{
  "id": 1, "user_id": 1, "title": "string", "model": "string",
  "provider": "ollama|openrouter", "matter_id": null, "created_at": "ISO8601"
}]
```

### POST `/api/chats`
```json
// Request
{ "title": "string (optional, default 'New Chat')", "model": "string", "provider": "string (optional)" }
// Response 200 — created chat object
```

### PUT `/api/chats/{chat_id}`
```json
// Request
{ "title": "string" }
// Response 200 — chat object
```
The response returns `provider` and `matter_id` as `null` whatever is stored; re-read the list for those.

### DELETE `/api/chats/{chat_id}`
Returns `{ "message": "Chat deleted" }`. The chat's messages and documents go with it.

### POST `/api/chats/{chat_id}/matter`
Assign the chat to one of the caller's matters, or unassign it with `null`.
```json
// Request
{ "matter_id": 3 }
// Response 200 — chat object
```
`404 Matter not found` if the matter is not the caller's.

### GET `/api/chats/{chat_id}/messages`
Returns the chat's messages ordered by `created_at ASC`.
```json
[{
  "id": 1, "chat_id": 1, "role": "user|assistant",
  "content": "string", "model": "string|null", "provider": "string|null",
  "rating": null, "feedback_comment": null, "cost_usd": null,
  "sources": null, "research_plan": null,
  "research_mode": "string|null", "chat_mode": "string|null",
  "created_at": "ISO8601"
}]
```

### POST `/api/chats/{chat_id}/messages`
The client saves both halves of each exchange here after the stream ends.
```json
// Request
{
  "role": "user|assistant", "content": "string",
  "model": "string|null", "provider": "string|null", "cost_usd": 0.0012,
  "sources": [ ... ],            // assistant: the `sources` from the `result` event
  "research_plan": { ... },      // assistant, Deep Research: the approved plan
  "research_mode": "string",     // assistant: as echoed on the `result` event
  "chat_mode": "string"
}
// Response 200 — created message object
```
`research_mode` and `chat_mode` on an assistant message are what the server later reads from the history to detect a mode change between turns (see `mode_change` in §5).

### PUT `/api/chats/messages/{message_id}/rating`
```json
// Request
{ "rating": 4, "comment": "string (optional)" }
// Response 200 — updated message object
```
`rating` must be 1–5, otherwise `400`.

## 3. AI (`/api`)

### GET `/api/models` — Auth required
Returns the active provider's model list, with `active: true` on the configured default (the first model is marked if the configured one is not in the list).
```json
[{ "name": "string", "context_length": 262144, "provider": "ollama|openrouter", "active": true }]
```

### POST `/api/chat` — Auth required
SSE streaming endpoint (`text/event-stream`). Each event is `data: {...}\n\n`. The request waits for a slot on the active provider's request queue.

Request body (shared with `/api/system/chat`; defined once in `routers/agent_request.py`):

| Field | Default | Notes |
|---|---|---|
| `messages` | required | Conversation history, `[{ "role", "content", ... }]`. Assistant entries may carry `research_mode` / `chat_mode` as stored. |
| `model` | required | Must be non-empty, but the server runs the active provider's **configured** model; this value is used only when none is configured. |
| `num_ctx` | `null` | Context-window hint passed to the provider. |
| `chat_mode` | `"research"` | `conversational`, `research` or `deep_research`. |
| `deep_research_plan` | `null` | The approved plan, required when `chat_mode` is `deep_research`: `{ "scope_note": "", "steps": [{ "id": 1, "title": "", "detail": "" }] }`. 1–8 steps; `title` 1–500 characters, `detail` up to 4,000, `scope_note` up to 2,000 (`422` otherwise). |
| `research_mode` | `"legislation_only"` | `legislation_only`, `case_law_only` or `legislation_and_case_law`. Ignored when the bot's `RESEARCH_MODE` environment variable is set (the parliament bot's `parliamentary_records`, the Westminster bot's `westminster_records`): that value always wins. |
| `chat_id` | `null` | Loads the chat's uploaded documents (§16) and its matter (§15) into the agent's context. |
| `jurisdiction`, `year_from`, `year_to`, `date_from`, `date_to`, `legislation_type` | `null` | Research filters. |
| `record_type`, `sessions` (integer array), `house` | `null` | Parliamentary filters, read only by the parliament and Westminster bots (`house` by Westminster only). |

The former `court` and `current_only` filters were removed; a client still sending them gets the same response and the values are discarded.

An empty `messages` or `model`, or `chat_mode: "deep_research"` without a plan, returns HTTP 200 with a stream holding a single `error` event (unlike `/api/system/chat`, which returns `400`).

SSE event types:

| Type | Shape | Description |
|---|---|---|
| `queue` | `{ "type": "queue", "position": 2 }` | Waiting for a slot on the provider's request queue |
| `token` | `{ "type": "token", "content": "..." }` | Streamed answer text (the Manager, or the Deep Research synthesis) |
| `tool_start` | `{ "type": "tool_start", "tool": "...", "id": "..." }` | Progress. `tool` is a display label: `"Research Agent"`, `"Research Agent — Step N: <title>"`, `"Worker: <tool name>"`, `Querying <peer name> - "<question>"`, or summarisation progress (which carries no `id`) |
| `tool_end` | `{ "type": "tool_end", "tool": "...", "id": "...", "result": "..." }` | The matching completion; `result` is a short status label, not the tool output |
| `api_call_start` | `{ "type": "api_call_start", "id": "...", "url": "...", "method": "POST", "payload": {...} }` | External API request made by a Worker tool |
| `api_call_end` | `{ "type": "api_call_end", "id": "...", "url": "...", "status": 200, "response": {...}, "elapsed_ms": 412 }` | Its outcome |
| `warning` | `{ "type": "warning", "message": "..." }` | Sent once if the request is still running after 5 minutes |
| `timing` | `{ "type": "timing", "request_id": "...", "total_ms": 0, "queue_wait_ms": 0, "llm_calls": 0, "total_cost_usd": 0.0, ... }` | Performance and efficiency metrics for the request, sent immediately before `result` |
| `result` | `{ "type": "result", "message": { ... } }` | Final response (below) |
| `error` | `{ "type": "error", "error": "..." }` | Human-readable failure |

Display labels are for the UI and may change; a machine consumer should use `/api/system/chat` and its `audit` event instead of matching them.

The `result` message:
```json
{
  "role": "assistant",
  "content": "markdown answer",
  "model": "string",
  "provider": "ollama|openrouter",
  "research_mode": "legislation_only",
  "chat_mode": "research",
  "sources": [{ "n": 1, "kind": "string", "title": "string", "url": "string", "cite": "string" }],
  "suggestions": ["string"],
  "stats": { "prompt_eval_count": 0, "eval_count": 0 }
}
```
- `research_mode` / `chat_mode` echo the modes the reply ran under; the client saves them on the assistant message (§2).
- `sources` is present only when the answer has sources. Entries are numbered by `n`; extra keys vary by source type (e.g. `sub`, `excerpt`, `meta`, `year`, `extent`).
- `suggestions` (up to 4 follow-up questions or clarification options, rendered as one-click chips) is present only when the model produced some and the `suggested_questions_enabled` flag is on. The tagged block is always stripped from `content`.
- `stats` is present when the provider reported token usage.
- Present only when they apply: `research_incomplete` (`{ "reason": "step_cap", "halts": [...], "disclosed": bool }`), `research_lost` (`{ "reason": "empty_completion", "lost": [...], "disclosed": bool, ... }`), `answer_failed: true` (the Manager returned nothing and the answer is a labelled fallback) and, for Deep Research, `synthesis_failed: true`.
- There is no `cost_usd` in the message; the request's cost is `total_cost_usd` on the `timing` event.

After the stream ends the server persists a `request_timings` row and, for a breach of the bot's efficiency profile, an `EFFICIENCY` activity-log row.

## 4. System Chat (`/api/system`) — Auth required

### POST `/api/system/chat`
Machine-to-machine variant of `/api/chat` for evaluation harnesses. Accepts **exactly** the `/api/chat` body (the model subclasses it, so parity is structural) plus two audit-only fields:

| Field | Default | Purpose |
|---|---|---|
| `audit` | `true` | Emit the structured `audit` event |
| `audit_max_field_chars` | `0` | Truncate long strings in the trace; `0` = no truncation |

Runs the same pipeline with `emit_tool_details=True`, so in addition to the `/api/chat` events it relays:
- `tool_call` — `{ "type": "tool_call", "tool_calls": [...] }`, the model's tool-call payload
- `tool_result` — `{ "type": "tool_result", "tool": "...", "result": "..." }`, the text returned to the model
- `audit` — **structured trace of the whole run** (schema version 6), emitted once immediately before `result`, and also before the `error` event when a run fails

It does not send the 5-minute `warning` event.

Deep Research works here exactly as on `/api/chat`: draft a plan with `POST /api/research/plan` (§5), then send it back as `deep_research_plan` with `chat_mode: "deep_research"`. Sending `chat_mode: "deep_research"` **without** a plan is a `400`, not a silent fall-through to standard research. Empty `messages` or `model` is also a `400`.

Timing rows are persisted with `source = "eval"` so evaluation traffic stays separable from app traffic in the Efficiency and Cache tabs (the dashboards do not yet filter on it). No efficiency-breach activity rows are written for eval runs.

See `docs/api/AUDIT_TRACE.md` for the full `audit` event schema and consumer guidance.

## 5. Deep Research Planning (`/api/research`) — Auth required

### POST `/api/research/plan`
Deep Research Phase A: runs the planner (an LLM call with no research tools) and returns the drafted plan as plain JSON, not SSE. It takes a slot on the same per-provider request queue as `/api/chat`. Execution of the approved plan goes through `/api/chat` (§3).

The body is the `/api/chat` body without `chat_mode` and `deep_research_plan` (planning is always Deep Research): `messages`, `model`, `num_ctx`, `research_mode`, the filters and `chat_id`. `chat_id` is accepted, but the planner does not load the chat's documents or matter.

```json
// Response 200 — a plan
{
  "plan": { "scope_note": "string", "steps": [{ "id": 1, "title": "string", "detail": "string" }] },
  "mode_change": null
}

// Response 200 — or a clarifying question
{ "needs_clarification": true, "question": "string", "options": ["string"], "mode_change": null }
```
- A plan has at most 8 steps.
- `options` holds at most 4 one-click answers; it is `[]` when the `suggested_questions_enabled` flag is off.
- `mode_change` is `null`, or `{ "research_mode": { "from", "to" } | null, "chat_mode": { "from", "to" } | null }` when the modes differ from those stamped on the previous assistant message in `messages`.

Errors (`detail` is a sentence for the user):
- `422` — empty `messages` or `model`.
- `502` — the provider declined the account (provider `401`/`402`/`403`; returned as `502` so the client does not log the user out), the planner called neither of its tools, or another failure.
- `503` — provider configuration could not be read, the provider is unreachable, rate-limited (`429`) or returned another error.

## 6. Users (`/api/users`) — Admin only

### GET `/api/users`
Returns all users ordered by `id`: `[{ "id", "username", "role", "email", "created_at" }]`.

### POST `/api/users`
```json
{ "username": "string", "password": "string", "role": "user|admin (default user)", "email": "string (optional)" }
```
Returns `201` with the user object. A duplicate username or email, or a missing username or password, is `400`.

### PUT `/api/users/{user_id}`
Partial update — any combination of `username`, `role`, `email`, `password` (a blank password is ignored). `404` if the user does not exist; `400` on a duplicate username or email.

### DELETE `/api/users/{user_id}`
Returns `{ "message": "User deleted" }`. Deleting your own account is `400`; deleting the account named `admin` is `403`.

### GET `/api/learning/stats`

### POST `/api/learning/test`
```json
// Request
{ "query": "string" }
// Response — retrieval results matched to the query
{ "examples": [{ "chat_id", "question_time", "question", "answer", "rating", "feedback_comment" }], "critiques": [{ "question", "rating", "feedback_comment" }] }
```
An empty `query` is `400`.

## 8. Statistics (`/api/stats`) — Admin only

Every `GET` takes `days` (integer or `"all"`, default 30; an unrecognised value means 30), except `/parliament-coverage`.

### GET `/api/stats/usage`
Returns KPIs, daily activity, chats per model and top users.
```json
{
  "kpi": { "users": 12, "chats": 340, "messages": 2100, "activeUsers": 8 },
  "activity": [{ "date": "...", "count": 0 }],
  "models": [{ "model": "...", "count": 0 }],
  "topUsers": [{ "username": "...", "msg_count": 0 }]
}
```

### GET `/api/stats/performance`
Request timing from `request_timings`: `{ "kpi", "daily", "llmDistribution", "slowest" }` — totals, p95, LLM and LEX API call counts and times, time to first token, queue wait.

### GET `/api/stats/cost`
`{ "kpi", "daily", "perUser", "priciest" }`. KPIs, daily spend and the priciest requests come from `request_timings.total_cost_usd`; per-user totals from assistant `messages.cost_usd`.

### GET `/api/stats/efficiency`
Manager→Worker loop efficiency: `{ "kpi", "indicators", "thresholds", "researchMode", "daily", "worst", "byModel" }`. Mode-aware: the bot's `RESEARCH_MODE` selects the efficiency profile (fan-out denominator, indicator bands, and the search-budget indicator on the parliament bot), echoed as `thresholds`. Counts research requests with at least one delegation; Deep Research rows are excluded. `byModel` is the report-structure reformat rate per model.

### GET `/api/stats/cache`
Caching savings: `{ "kpi", "daily", "recentHits", "localCache", "localCacheTop", "flags" }` — tool-memo hits, provider prompt caching (cached tokens, Anthropic cache discount), local prompt cache hits and characters saved, the cache table's own contents (independent of `days`), and the current state of the caching feature flags.

### DELETE `/api/stats/cache/local`
Purges the whole local prompt cache. Returns `{ "deleted": 123 }`.

### GET `/api/stats/parliament-coverage`
Query param: `session` (`"all"` or a Holyrood session id such as `"6"`; anything else means `"all"`). Ingest coverage of the crawled Scottish Parliament data: `{ "session", "sessions", "committee", "plenary", "video", "perSession" }`. Meaningful on the parliament bot.

## 9. Developer Tools (`/api/developer`)

Admin only, except where marked.

### Provider configuration

#### GET `/api/developer/provider-config`
```json
{
  "active_provider": "ollama|openrouter",
  "providers": [{
    "id": "ollama", "name": "Ollama (Local)",
    "model_list": [{ "name": "...", "context_kb": 256 }],
    "config": { "base_url": "...", "api_key": "...", "model": "...", "summarisation_model": "...", "temperature": 0.3, "max_concurrent_requests": 2, "max_summarise_concurrency": 1, "_model_context_length": 262144 }
  }, { "id": "openrouter", "name": "OpenRouter", "model_list": [], "config": { ... } }]
}
```
`config` is the resolved configuration (database values over `.env` defaults). **It includes the stored `api_key` in clear**; treat the response as sensitive.

#### POST `/api/developer/provider-config`
```json
{ "provider": "ollama|openrouter", "config": { "base_url": "...", "api_key": "...", "model": "...", "summarisation_model": "...", "temperature": 0.3, "max_concurrent_requests": 2, "max_summarise_concurrency": 1 } }
```
Only the seven keys shown are kept. The stored settings are **replaced**, not merged: a key left out falls back to its `.env` default. Unsupported provider: `400`. Returns `{ "success": true }`. Takes effect on the next request; no restart.

#### POST `/api/developer/active-provider`
```json
{ "active_provider": "ollama|openrouter" }
```
Returns `{ "success": true, "active_provider": "..." }`; unsupported provider: `400`.

#### GET `/api/developer/openrouter-models`
Fetches the live model list from OpenRouter's `/models` (cached in process for 5 minutes): `{ "models": [{ "name": "...", "context_kb": 128 }] }`. `400` if no OpenRouter key is configured; `502` if OpenRouter cannot be reached or returns an error.

### Feature flags

#### GET `/api/developer/features` — Auth required
Returns the flag set, merged over the defaults so a flag saved before it existed reads as its default:

| Flag | Default | Effect |
|---|---|---|
| `matters_enabled` | `true` | Off: every `/api/matters` route returns `403` |
| `prompt_caching_enabled` | `true` | Provider prompt caching (`cache_control` on Anthropic models) |
| `tool_memo_enabled` | `true` | Per-request tool-result memo |
| `local_prompt_cache_enabled` | `true` | Cross-user cache of Worker document summaries |
| `research_mode_enabled` | `true` | Whether the client offers the Research chat mode; the conversational prompt only points users at it when on |
| `deep_research_mode_enabled` | `true` | Whether the client offers Deep Research |
| `suggested_questions_enabled` | `true` | Suggested-question and clarification-option chips (`suggestions`, planner `options`) |
| `weekly_survey_enabled` | `false` | Whether the client shows the weekly survey |
| `session_feedback_enabled` | `false` | Whether the client shows the end-of-session feedback form |
| `scts_caselaw_enabled` | the `SCTS_CASELAW_ENABLED` setting until first saved | Scottish judgments (SCTS) searched alongside Find Case Law |
| `drafting_mode_enabled` | `true` | Unused: stored and passed to the request config, read by nothing |

The server does not refuse requests on `research_mode_enabled`, `deep_research_mode_enabled`, `weekly_survey_enabled` or `session_feedback_enabled`; they decide what the client offers.

#### POST `/api/developer/features`
Body: the flags above. `matters_enabled` is required; every other flag left out is **saved at the default shown** (not left at its stored value), except `scts_caselaw_enabled`, which falls back to the `SCTS_CASELAW_ENABLED` setting. Returns `{ "success": true, "features": { ... } }`. Takes effect on the next request.

### Activity log

#### GET `/api/developer/activity-log`
Query params: `days` (integer or `"all"`, default 7), `limit` (default 500), `event_types` (comma-separated), `username`. Returns `[{ "event_type", "username", "description", "created_at" }]`, newest first. `LOGIN`, `EFFICIENCY` and `RESTORE` rows are stored; `QUERY`, `RESPONSE` (message excerpts up to 2,000 characters, reasoning blocks stripped), `SURVEY`, `FEEDBACK` and `ERROR` (failed health checks) rows are synthesised from other tables. Filters are applied before the limit. The role check is in the handler (`403` for non-admins).

### Users export

#### GET `/api/developer/users-export`
Returns `{ "csv": "name,email,role\r\n...", "count": 12 }` for copy and paste.

### Data clearing (Danger Zone)

#### GET `/api/developer/data-counts`
Rows each scope would delete: `{ "scopes": { "chats": "Chats & messages", ... }, "counts": { ... }, "details": { "chats": { "chats", "messages", "documents" }, "feedback": { "surveys", "sessions", "rated_messages" } } }`.

#### POST `/api/developer/clear-data`
```json
{ "scopes": ["chats", "performance", "feedback", "activity", "health", "cache"], "confirm": "DELETE" }
```
Deletes the selected scopes, in a fixed order whatever order they are sent in. `feedback` deletes survey and session-feedback rows and clears message ratings in place. Users, settings (provider configuration and feature flags), peers, matters and the crawled parliamentary corpus are never touched. `400` for a wrong confirmation phrase, an unknown scope or no scope. Returns `{ "success": true, "deleted": { "chats": 0, ... }, "message": "..." }`.

### Backup and scoped restore

#### GET `/api/developer/backups`
Backup runs for this bot's database under `BACKUP_ROOT`, newest first: `{ "backup_root", "root_exists", "database", "runs": [...], "latest", "latest_ok", "scopes", "confirm_phrase": "RESTORE", "components" }`. Each run carries its manifest provenance (status, timings, commit, sizes, verification) and `restorable`.

#### POST `/api/developer/restore/preflight`
```json
{ "run_id": "string", "scopes": ["feedback"] }
```
Dry run: stages the dump and reports exactly what a restore would change, by the same code as the real restore with the writes withheld. Returns the restore result (below) with `dry_run: true`. `400` for an unknown run or scope; `500` on failure.

#### POST `/api/developer/restore`
```json
{ "run_id": "string", "scopes": ["feedback"], "confirm": "RESTORE" }
```
Restores the selected scopes from a backup into the live database (additive; the current contents are dumped first so the restore can be undone). Returns `{ "success": true, "dry_run": false, "run_id", "database", "dump_file", "commit_sha", "backup_started_at", "scopes", "components": [...], "total_rows", "sequences_reset", "safety_dump", "duration_s" }`. A `RESTORE` activity-log row is written on success and on failure. `400` for a wrong confirmation phrase or an invalid request; `500` on failure. The `cache` scope can never be restored: its rows are excluded from every dump.

### Parliamentary data refresh

#### GET `/api/developer/parliament-refresh`
`{ "research_mode", "supported", "sessions": [{ "id", "label" }], "status": { ... } }`. `supported` is true only on a bot running in `parliamentary_records` mode.

#### POST `/api/developer/parliament-refresh`
```json
{ "session": "all|1|2|3|4|5|6|7" }
```
Starts a background re-crawl of one Holyrood session and returns at once: `{ "success": true, "session": "6" }`. Poll the `GET` for progress. `400` on a bot not in `parliamentary_records` mode or for an unknown session; `409` if a refresh is already running.

## 10. Health (`/api/health`) — Public

None of these routes takes an authentication dependency.

### GET `/api/health`
Simple liveness check. Returns `{ "status": "healthy" }`.

### GET `/api/health/status`
The latest stored check for the database, the LEX API and the active LLM provider:
```json
{
  "database": { "is_healthy": true, "error_message": null, "latency_ms": 12, "checked_at": "ISO8601" },
  "lex_api": { ... },
  "llm": { ... },
  "active_llm_provider": "ollama|openrouter"

```
A service with no stored check reads `is_healthy: null` and `"No data available yet."`. If the database cannot be read, a live check is run instead.

### GET `/api/health/history`
Query params: `service` (required: `database`, `lex_api`, `ollama` or `openrouter`), `limit` (default 100). Returns the service's last `limit` checks, oldest first: `[{ "is_healthy", "error_message", "latency_ms", "checked_at" }]`.

### POST `/api/health/trigger`
Runs a health check of every service immediately (checks also run every 5 minutes in the background) and returns the same object as `/status`.

## 11. Feedback (`/api/feedback`)

The `GET` routes check the role in the handler and return `403` for non-admins.

### POST `/api/feedback` — Auth required
The weekly survey. Every field is optional.
```json
{ "message": "string", "time_saved_hours": 1.5, "time_without_aila_hours": 3.0, "confidence": 4, "usability": 4, "verification_hours": 0.5 }
```
Hours must be non-negative and `confidence` / `usability` 1–5, otherwise `400`. Returns `201 { "status": "ok" }`.

### GET `/api/feedback` — Admin only
Query param: `days` (integer or `"all"`, default 30). Returns survey responses with the username, newest first.

### GET `/api/feedback/compliance` — Admin only
Survey compliance over the last four calendar weeks: `{ "weeks": [{ "label", "start_date", "end_date", "is_current" }], "users": [{ "user_id", "username", "weeks": [{ "query_count", "survey_submitted" }] }] }`.

### POST `/api/feedback/session` — Auth required
The end-of-session feedback form. Every field is optional:
`chat_id`, `message_count`, `manual_time_hours`, `time_saved_hours`, `verification_hours`, `session_continuity` (`one_go` | `not_one_go`), `found_right_law`, `right_jurisdiction`, `references_accurate`, `refers_incorrectly` (each `yes` | `partially` | `no`) with a matching `*_notes` text field (`references_notes` for `references_accurate`), `confidence` and `ease_of_use` (1–5), `ease_of_use_reason`, `other_comments`, `filters` (the filter panel's state; unknown keys and wrong types are dropped) and `finished_seconds_ago` (0–7,200: seconds since "Finished session" was pressed, resolved against the server's clock).

An out-of-range value is `400`. A `chat_id` the caller does not own is stored as `null`. Returns `201 { "status": "ok" }`.

### Session feedback reads — Admin only
Each takes `days`: an integer, `"all"`, or `"prepilot"` (the pre-pilot run, 11–19 August 2026 inclusive, UK days). The operator account `admin` is excluded throughout.
- **GET `/api/feedback/session`** — the responses, one per thread (a later form on the same thread supersedes an earlier one; forms without a `chat_id` are all returned), with `chat_title`, the derived `session_mode` and `finished_at`.
- **GET `/api/feedback/session/transcripts`** — full transcripts of the same threads: `[{ "chat_id", "messages": [{ "role", "content", "model", "provider", "cost_usd", "rating", "feedback_comment", "deep_research", "created_at" }] }]`. Can be large.
- **GET `/api/feedback/session/durations`** — session lengths for threads with a form: `{ "days", "cap_seconds", "summary", "uncapped", "quality", "sessions" }`. Durations are capped at 4 hours; `uncapped` reports the figures without the cap.
- **GET `/api/feedback/session/compliance`** — per user: queries, threads, responses, threads covered, and all-time `last_active` / `last_feedback`: `{ "days", "totals", "users" }`.

### GET `/api/feedback/message-ratings` — Admin only
Query param: `days` (integer or `"all"`, default 30). Rated assistant messages with the question that prompted each: `[{ "id", "rating", "feedback_comment", "response", "query", "username", "chat_title", "created_at" }]`.

  "bot_id": "string", "name": "string", "tagline": "string",

### GET `/api/bot/logo`
Streams the configured logo file (`bot_identity.logo_path`, relative to the repository root). `404` if not configured or missing.

## 13. Federation (`/api/consult`) — Auth required

Machine-to-machine endpoint by which a sibling bot's Manager consults this bot. Synchronous JSON (not SSE) — the caller blocks until the full answer is returned. The caller authenticates with a Bearer token: in practice the non-expiring token from `POST /api/auth/federation-token` on this bot, stored as `api_key` in the caller's peer registry. Any valid token is accepted.

### POST `/api/consult`
```json
// Request
{ "question": "string", "depth": 0 }
// Response 200
{ "answer": "string", "bot_id": "string", "bot_name": "string" }
```
The question runs through this bot's Manager in its own research mode, as a single stateless turn: the consulted bot never asks a clarifying question and returns no suggestions. It does not take a slot on the request queue. A request arriving with `depth >= 2` is rejected with `422` to prevent A→B→C cascade loops; any onward consult is sent with `depth + 1`.

## 14. Peers (`/api/peers`) — Admin only

Federation peer registry CRUD (Admin Portal → Federation tab). `api_key` is the credential this bot sends to the peer as a Bearer token. It is **write-only** — never returned by any response; `has_api_key: true/false` is returned instead.

Peer object: `{ "id", "peer_id", "name", "base_url", "has_api_key", "description", "enabled", "created_at" }`.

- `GET /api/peers` — list registered peers, oldest first.
- `POST /api/peers` — register a peer: `peer_id`, `name`, `base_url`, `description` (required), `api_key` (optional), `enabled` (default `true`). `201`; `409` if the `peer_id` exists.
- `PUT /api/peers/{peer_id}` — partial update (uses the **string** `peer_id`, e.g. `parliament_bot`, not the numeric row id). An omitted or `null` `api_key` keeps the stored one. `404` if not found.
- `DELETE /api/peers/{peer_id}` — remove a peer. `204`; `404` if not found.

Peers listed in `bot_config.json`'s `peer_registry_seed` are inserted at startup if absent; an existing row is never updated by the seed.

## 15. Matters (`/api/matters`) — Auth required

Matter (workspace) management and per-matter notes and brief. Every route acts only on the caller's own matters (`404` otherwise) and returns `403` while the `matters_enabled` flag is off.

Matter object: `{ "id", "user_id", "title", "description", "status", "jurisdiction", "legislation_type", "note_count", "created_at", "updated_at" }`. `status` is `open` (the default) or `closed`.

- `GET /api/matters` — the caller's open matters, newest first; `?include_closed=true` includes closed ones.
- `POST /api/matters` — create: `{ "title", "description", "jurisdiction", "legislation_type" }` (only `title` required).
- `PUT /api/matters/{matter_id}` — partial update of `title`, `description`, `status`, `jurisdiction`, `legislation_type` (an empty string clears the last two).
- `DELETE /api/matters/{matter_id}` — returns `{ "message": "Matter deleted" }`.
- `GET /api/matters/{matter_id}/notes` — the matter's notes, oldest first: `[{ "id", "matter_id", "content", "message_id", "created_at" }]`.
- `POST /api/matters/{matter_id}/notes` — add a note: `{ "content", "message_id" (optional) }`.
- `DELETE /api/matters/{matter_id}/notes/{note_id}` — returns `{ "message": "Note deleted" }`.
- `POST /api/matters/{matter_id}/brief` — `{ "mode": "brief|gaps" }` (default `brief`). Composes the assistant messages of the matter's chats (up to 80,000 characters) into a briefing note, or with `gaps` a numbered list of research gaps, in one tool-free call to the active provider. Returns `{ "content": "markdown" }`; a matter with no chats or no answers returns a one-line explanation instead.

Assigning a chat to a matter is `POST /api/chats/{chat_id}/matter` (§2).

## 16. Documents (`/api/chats` / `/api/documents`) — Auth required

Per-chat document upload. The extracted text is given to the agent as context on each `/api/chat` request that sends the chat's `chat_id` (up to 80,000 characters across the chat's documents).

- `POST /api/chats/{chat_id}/documents` — upload one file as multipart form field `file`. Accepted types: PDF, DOCX, TXT, MD (`.text` too). Limit 20 MB (`413`); text is cut at 50,000 characters. Returns `{ "id", "filename", "size_bytes", "char_count", "excerpt", "created_at" }` (`excerpt` is the first 200 characters). `400` for an unsupported type, `422` when no text can be extracted, `404` if the chat is not the caller's.
- `GET /api/chats/{chat_id}/documents` — the chat's documents, oldest first: `[{ "id", "filename", "size_bytes", "char_count", "created_at" }]`.
- `DELETE /api/documents/{doc_id}` — delete one of the caller's documents. `204`; `404` if not found.
