## 1. Background context (read this first)

### What the bot does today
The **parliament bot** (`bots/parliament/`, `RESEARCH_MODE=parliamentary_records`, DB `lexchat_parliament`,
port 8001) searches **Scottish Parliament (Holyrood) only** — plenary (chamber) debates and committee
transcripts. Two DB-backed search tools drive retrieval:

- `search_scottish_plenary` → `_search_plenary_db` in [`server_py/src/agent/tools/parliament.py:327`](../../server_py/src/agent/tools/parliament.py#L327)
- `search_scottish_committee_transcripts` → `_search_committee_transcripts_db` in [`parliament.py:451`](../../server_py/src/agent/tools/parliament.py#L451)

Both run **PostgreSQL lexical FTS** — `to_tsvector('english', full_text) @@ plainto_tsquery('english', :query)`
ranked by `ts_rank`, `LIMIT 10`. Data lives in `sp_plenary_items` and `sp_committee_items`
([`server_py/src/models.py:244` and `:265`](../../server_py/src/models.py#L244)), each row = one **agenda item**
with a `full_text` column (GIN FTS index) and a `speeches` JSON column (parsed per-contribution list).
Tables are populated by [`server_py/src/services/parliament_crawler.py`](../../server_py/src/services/parliament_crawler.py)
(one-shot backfills + daily rolling crawls). `_build_full_text` there concatenates `speeches` into `full_text`.

### Why this change
Lexical FTS only matches words that literally appear (plus English stemming: `dogs`→`dog`). It misses
synonyms and concepts — a search for *canine welfare* won't find a speech that only says *dog*. This adds
**semantic retrieval**: embed the query into a vector, find speeches whose embeddings are nearest by cosine
similarity, and **fuse** those with the existing FTS results (hybrid search). FTS is kept — it's better at exact
terms (Act names, section numbers, member surnames) that embeddings blur.

### Hard deployment constraints (these shape every choice)
From `CLAUDE.md`: target is **Windows Server 2022, internet-restricted (whitelist-only), no Docker/WSL,
native**. PostgreSQL **15** runs as a Windows service. Python deps install **globally from offline wheels**
(`binaries/offline_dependencies.zip`, regenerated by `deployment/package_offline_native.ps1`). Ollama runs as
a local process and is already in the stack. The frontend is pre-built and committed. Deployment is **git pull
on the target** — commit + push together.

### Locked architecture decisions (agreed 2026-07-07)
- **Hybrid, not replacement** — FTS + vector merged by **Reciprocal Rank Fusion (RRF)**. Tool names unchanged
  (`search_scottish_plenary`, `search_scottish_committee_transcripts`) so the Worker prompt, `search_budget`,
  `_apply_parliament_filters`, and Phase-2 nudges are all untouched.
- **Vector store: pgvector + HNSW** (`vector_cosine_ops`).
- **Embeddings: local Ollama** `nomic-embed-text` (**768-dim**). OpenRouter has no embeddings endpoint, so this
  is provider-independent config (`AppSetting(key="provider.embedding")`), not tied to the active chat provider.
- **Chunk unit = one embedding per speech.** The `speeches` JSON already exists; avg speech ≈ 215 tokens, inside
  the model window. Sub-split only speeches over a threshold.

### Measured corpus (from `lexchat_parliament`, 2026-07-07)
| | Meetings | Agenda items | Speeches | Dates |
|---|---|---|---|---|
| Plenary | 11 | 76 | 2,964 (39/item, avg 857 chars) | 2026-06 only (~3 wks) |
| Committee | 244 | 629 | 718 (**1.1/item — under-parsed**) | 2021-06 → 2026-06 |

**Full Session 6 + 7 estimate: ~250K–400K speeches → ~250K–400K vectors** (~2–3 GB with HNSW; ~1 hr one-time
embedding backfill through local Ollama, must be resumable). This is why pgvector (not brute-force numpy) is used.

> `speeches` is stored as Postgres `json` (not `jsonb`) — use `json_array_length` / `json_array_elements_text`
> in any raw SQL against it.

## 2. Prerequisites (P0 — do before the phases)

- **P0a — pgvector install spike.** `vector` is **not** in `pg_available_extensions` on local Postgres 18 or
  target Postgres 15. No build toolchain on target → obtain the **prebuilt Windows binary for PG15**
  (`vector.dll` → `<pg>/lib`, `vector.control` + `vector--*.sql` → `<pg>/share/extension`), then
  `CREATE EXTENSION vector;`. **Prove it drops into local Postgres first.** If this fails, the whole design
  changes — do it before anything else.
- **P0b — fix committee speech parsing.** 1.1 speeches/item is a parser bug (the plenary-vs-committee parser
  asymmetry noted in `CLAUDE.md`). Semantic recall is only as good as the parsed speeches, so fix
  `_parse_sp_*_transcript` for committee pages before the backfill, else half the corpus is empty.
- **P0c — Session 6 plenary backfill.** Crawler supports `dateSelect=custom`; `backfill_plenary()` just hasn't
  run the full Session 6 range (2021-05-13 →). This is crawl time (~hours), not dev work, but it gates the
  embedding backfill. Run after P0b so committee re-parse and plenary backfill land together.

## 3. Phased implementation

### Phase 1 — pgvector + Python dependency
- Install the extension (P0a) on local + document the target steps in `deployment/NATIVE_DEPLOYMENT.md`.
- Add `pgvector==0.3.*` (the Python package: SQLAlchemy `Vector` type + psycopg/asyncpg adapters) to
  [`server_py/requirements.txt`](../../server_py/requirements.txt). **This requires regenerating the offline
  bundle** (`deployment/package_offline_native.ps1`) — note it in the requirements header comment like the
  existing pdfplumber note.
- In `database.py` init, add `CREATE EXTENSION IF NOT EXISTS vector;` before table/index creation.

### Phase 2 — embedding module + config
- New file `server_py/src/agent/embeddings.py`:
  - `async def embed_texts(texts: list[str]) -> list[list[float]]` — POST `{_base_url()}/api/embed`
    `{"model": <embed_model>, "input": texts}`, `headers=_get_headers()`, `httpx.AsyncClient(verify=False)`,
    returns `resp["embeddings"]`. Batch (e.g. 32/call). Mirror the client/header pattern in
    [`ollama_client.py:22-28`](../../server_py/src/agent/ollama_client.py#L22).
  - `async def embed_query(text: str) -> list[float]` — single-input convenience.
  - Config resolved from a new `AppSetting(key="provider.embedding")` (`base_url`, `api_key`, `model`, `dim`);
    fall back to `.env` `EMBEDDING_MODEL` / Ollama base URL. Add getters to
    [`provider_factory.py`](../../server_py/src/agent/provider_factory.py) alongside the existing
    `get_provider_config` / `save_provider_config`. Reuse the RequestQueue/semaphore caching pattern to bound
    concurrency (Ollama = low concurrency).
  - Guard: if no embed model configured/reachable, `embed_query` returns `None` so callers fall back to pure FTS.

### Phase 3 — schema + migration
- New model in `models.py`: `SpSpeechEmbedding` (single table, `source` discriminator — less duplication than
  two tables, and there is no hard FK across the two item tables anyway):
  - `id` PK; `source` `String(16)` (`'plenary'` | `'committee'`); `item_id` `Integer` (the `sp_*_items.id`);
    `speech_idx` `Integer`; `chunk_idx` `Integer` (0 unless a long speech was sub-split); `speaker`
    `String(256)`; `chunk_text` `Text`; `embedding` `Vector(768)`; denormalized filter columns
    `meeting_date` `Date`, `committee_code` `String(64)`; `created_at`.
  - Unique constraint `(source, item_id, speech_idx, chunk_idx)` for idempotent re-embedding.
  - HNSW index: `CREATE INDEX ... USING hnsw (embedding vector_cosine_ops)`; b-tree on
    `(source, meeting_date)` and `(source, committee_code)` for filtered vector search; index on
    `(source, item_id)` for cascade cleanup.
- Add all `CREATE INDEX ... IF NOT EXISTS` to the `index_statements` list in
  [`database.py:~200`](../../server_py/src/database.py#L200).

### Phase 4 — backfill script + crawler hook
- `server_py/scripts/backfill_embeddings.py` (standalone, resumable):
  - Iterate `sp_plenary_items` then `sp_committee_items`, skipping items already fully embedded
    (`item_id` present in `SpSpeechEmbedding` with matching speech count) — makes it re-runnable.
  - For each item, read `speeches` JSON → per speech, `chunk_text` = speaker + text; sub-split speeches over
    ~1,600 chars (~400 tokens) with ~15% overlap. Batch-embed, bulk-insert with the denormalized
    `meeting_date`/`committee_code`. Log progress; commit per item so a crash resumes cleanly.
- Hook incremental embedding into the crawler: after `_insert_item` / `_insert_plenary_item` succeed in
  [`parliament_crawler.py`](../../server_py/src/services/parliament_crawler.py), embed that item's speeches so
  new meetings self-maintain. Keep it best-effort (wrap in try/except; a failed embed must not fail the crawl).

### Phase 5 — hybrid query (the core behaviour change)
Inside `_search_plenary_db` and `_search_committee_transcripts_db` in `parliament.py`:
1. Keep the existing FTS query but also select its `item_id` and FTS rank (top ~30).
2. `qvec = await embed_query(query)`. If `None`, behave exactly as today (pure FTS) — safe fallback.
3. Vector query (filters mirror the FTS filters — `source`, `meeting_date` range, `committee_code`):
   ```sql
   SELECT item_id, MIN(embedding <=> :qvec) AS dist
   FROM sp_speech_embeddings
   WHERE source = :source [AND meeting_date >= ... AND committee_code ILIKE ...]
   GROUP BY item_id
   ORDER BY dist ASC
   LIMIT 30;
   ```
   Bind `:qvec` via the `pgvector` SQLAlchemy adapter.
4. **RRF merge** the two ranked `item_id` lists: `score(item) = Σ 1/(k + rank_in_list)`, `k=60`. Take top 10
   item_ids, fetch their rows from `sp_*_items`, return the **same slim shape** already returned today
   (`meeting_id`, `slug`, `iob_id`, `meeting_date`, `agenda_item_title`, `url`, `excerpt`, + `committee_name`
   for committee). Retrieval tools (`get_scottish_plenary_debate` etc.) are unchanged.
- The `"table empty"` / `note` graceful-fallback pattern stays. Add an analogous note if embeddings are absent
  but FTS still runs.

### Phase 6 — admin config + docs
- Admin Portal → Developer tab: add an **Embedding** config panel (base URL, api key, model, dim) writing
  `provider.embedding` via the existing developer provider endpoints
  ([`routers/developer.py`](../../server_py/src/routers/developer.py)). Frontend
  ([`client/src/pages/AdminPortal.jsx`](../../client/src/pages/AdminPortal.jsx)) — reuse the existing provider
  form components; rebuild `client/dist` and force-add per the deploy workflow.
- Update `CLAUDE.md` (parliament section + Key Files), `bots/parliament/PARLIAMENTARY_DATA.md` (add embeddings
  to the availability matrix), and `deployment/NATIVE_DEPLOYMENT.md` (pgvector install + offline-bundle note).

## 4. Tests to run once implemented

### Unit
- `embeddings.embed_query` returns a 768-length float vector for a known string; returns `None` when the
  embed model is unconfigured (fallback path).
- Chunking: a >1,600-char speech splits into overlapping chunks; a short speech yields exactly one chunk.
- RRF merge: given two hand-built ranked lists, asserts the fused order matches the RRF formula (`k=60`).

### Integration (against a seeded `lexchat_parliament`)
- After Phase 3+4 on a small seed: `SELECT COUNT(*) FROM sp_speech_embeddings` ≈ total parsed speeches; every
  row has a non-null 768-dim `embedding`; unique constraint blocks duplicate re-embeds.
- **Semantic win case** — the original motivating query: search `"canine welfare"` and assert it returns a
  plenary/committee item whose text says *dog* but not *canine* (would be empty under pure FTS).
- **Exact-term still works** — a query with a specific Act name / member surname still ranks the literal match
  top (FTS half of the hybrid pulls its weight).
- **Filter parity** — `date_from`/`date_to` and `committee` still constrain results (vector half respects the
  denormalized filter columns).
- **Fallback** — with `provider.embedding` unset, both tools return the same results as pre-change FTS
  (no errors, `note` present).

### Manual / eval
- Curl `POST /api/chat` through the parliament bot with 5–10 concept queries (e.g. *dog welfare*, *ferry
  procurement*, *gender recognition*), compare hybrid vs FTS-only recall, confirm the Worker still completes
  within `search_budget` and Phase-2 retrieval still fires.
- Reachability: `server_py/test_apis.ps1` still green; Ollama `/api/embed` reachable from the box.

### Perf sanity
- On the full backfill, a hybrid query returns in < ~1 s (HNSW). Check `EXPLAIN` uses the HNSW index, not a seq
  scan; tune `hnsw.ef_search` if recall is low.

## 5. Rollback / safety
- Feature is **additive and gated**: unset `provider.embedding` → pure FTS, identical to today. No tool-schema
  or prompt changes, so the Worker/Manager behaviour is unaffected in the fallback.
- The `sp_speech_embeddings` table and pgvector extension are independent of existing tables — dropping them
  reverts fully.
- Commit `client/dist` + push together per the deploy workflow. Regenerate the offline bundle for the new
  `pgvector` wheel **before** the next air-gapped install.
